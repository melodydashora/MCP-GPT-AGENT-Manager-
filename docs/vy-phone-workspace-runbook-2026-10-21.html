1. Why a shortcut once "lost" the workspace

A shortcut cannot delete files, but it can start Claude Code somewhere other than the real workspace, which looks the same as lost work. The usual causes:

  • Wrong home. Logging in with --termux-home, or as a user other than root, hides everything in /root behind a different home folder.
  • Wrong folder. Claude Code keeps conversations per folder. Started in another folder it shows no history and none of the files.
  • A second Ubuntu. Installing the distro again under a slightly different name creates a fresh, empty one next to the real one.
  • Widgets. Home-screen shortcut widgets run with a stripped-down environment. Test from the Termux prompt first.
In every case the work is still on disk under the rootfs path in section 0. Check there before doing anything else.

2. Step 1: back up (from the outer Termux prompt, not inside Ubuntu)

This was the command that ran. It copies Ubuntu's /root/projects and /root/.claude into Termux's private storage. It prints nothing while it works and can take several minutes.

P=$(find $PREFIX/var/lib/proot-distro -maxdepth 5 -type d -path '*/root/projects' | head -1); R=${P%/root/projects}; echo "ROOTFS=$R"; ls "$R/root"
tar czf ~/backups/vy-root-$(date +%Y%m%d-%H%M).tgz -C "$R" root/projects root/.claude

"Permission denied" lines from find about sdcard, apex, system, vendor and similar are harmless. They are empty placeholder folders.

Verify

ls -lh ~/backups; tar tzf ~/backups/vy-root-*.tgz | wc -l

Good: a size in megabytes (not 20 bytes) and a file count in the thousands.

Restore, if ever needed (extracts into a safe side folder first)

mkdir -p ~/restore && tar xzf ~/backups/vy-root-YYYYMMDD-HHMM.tgz -C ~/restore && ls ~/restore/root

Then copy only what is missing back into $PREFIX/var/lib/proot-distro/containers/ubuntu/rootfs/root/.

3. Step 2: make sure an agent in Termux knows where everything is

Claude Code can read any file it is pointed at, but it only sees the folder it starts in, and its conversation history is kept per folder. Two changes:

  1. Start one level up, in /root/projects. Then VY, Astra's handoffs and checkpoints, and everything else are in one workspace.
  2. Leave a map. Claude Code reads CLAUDE.md from the start folder at every launch. Run this once inside Ubuntu (proot-distro login ubuntu first):
cat > /root/projects/CLAUDE.md <<'EOF2'
# Melody's phone workspace (Termux Ubuntu)
- vy-canis-majoris/ : VY Canis Majoris Android app source. Read docs/PRIORITY-FIXES-2026-10-21.md and docs/*.md first.
- my-project/astra/handoffs/ and my-project/astra/checkpoints/ : handoffs, checkpoints, day summaries and test results from Astra (Codex) and earlier Claude Code sessions. Read the newest ones before starting work.
- Also read /root/AGENTS.md: Astra's (Codex) working rules for this phone.
- Shared notes between all assistants: Melody Session Bridge MCP, namespace project.vy-canis-majoris. Roadmap key: plan.agent-dev-loop-and-play-packaging.20261020. Read hub/routing first.
- Rules: never Replit Agent. Never copy the upload keystore, API keys or tokens to /sdcard, the bridge or notes. Back up before editing. Report only tests actually run.
EOF2
cat /root/projects/CLAUDE.md

Codex reads AGENTS.md the same way; the existing /root/AGENTS.md already serves Astra. Gemini CLI reads GEMINI.md; copy the same text there if Gemini should see it.

To pick an older conversation from any folder: cd into that folder and run claude --resume.

4. Step 3: the shortcut (last; from the outer Termux prompt)

It logs into Ubuntu as root, moves to /root/projects, and resumes the newest conversation there. It refuses to run if the folder is missing instead of starting somewhere else.

mkdir -p ~/bin
cat > ~/bin/vy <<'EOF2'
#!/data/data/com.termux/files/usr/bin/sh
exec proot-distro login ubuntu -- bash -lc 'cd /root/projects || { echo "projects folder missing; not starting claude"; exit 1; }; exec claude --continue'
EOF2
chmod +x ~/bin/vy
grep -q 'HOME/bin' ~/.bashrc 2>/dev/null || echo 'export PATH="$HOME/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

First run: type vy at the Termux prompt and confirm it resumes the expected conversation. Skip the home-screen widget until that works.

5. If a workspace ever looks empty

proot-distro login ubuntu -- bash -lc 'echo HOME=$HOME; echo USER=$(whoami); pwd; ls -d /root/projects/vy-canis-majoris; ls /root/.claude/projects'
proot-distro list
ls $PREFIX/var/lib/proot-distro/containers/*/rootfs/root

Expect /root, root, the project folder, the four session folders, one container named ubuntu. If any differ, the files are still at the rootfs path; fix the login, do not reinstall.
